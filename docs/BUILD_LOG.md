# Build log: what broke and how it was fixed

Add a line every time something goes wrong. This is the script for the "what broke" part of the video.

| # | What broke | Why | Fix |
|---|---|---|---|
| 1 | The first prototype could not reach any job-board API (403 from the network) | The cloud sandbox only allowed a few websites | Moved the pipeline to GitHub Actions, which can reach the APIs, and run it there daily |
| 2 | Same opening showed twice: once from a job aggregator, once from the company site | Collected from both kinds of sources | Dropped aggregators entirely; only company job boards. De-dupe keeps one copy |
| 3 | One role became 3 cards (Bengaluru, Pune, Hyderabad) | Companies list each city as a separate post | Match on company + cleaned title, merge into one card with all cities |
| 4 | "Bangalore" and "Bengaluru", "Gurgaon" and "Gurugram" split the city filter | Every company spells cities differently | One canonical city list in config; the LLM may only answer with those names (schema enum) |
| 5 | "Remote" jobs from the US slipped in | "Remote" alone says nothing about the country | Remote counts as India only if the post mentions India |
| 6 | India check missed "Bengaluru, India" in tests | First regex was case-sensitive lowercase | Split into a case-insensitive word check and a case-sensitive code check (IN / IND). Caught by a unit test |
| 7 | A board that was down for a day would have "closed" all its jobs | Missing post was read as "job closed" | Track which boards answered; only close posts from boards that answered |
| 8 | Dates from Lever came as numbers | Lever sends epoch milliseconds | Date helper accepts both ISO strings and epoch ms |
| 9 | Keyword-only tagging put ~46% of posts in "Other" (79 of 171 in the preview) | Job titles are messy ("Intern - Community & Documentation") | This is why the LLM tags role; keyword tagger kept only as a fallback and a baseline |
| 10 | LLM could skip a post or return an unknown city | Models are not perfectly obedient | Strict tool schema with enums, validation after the call, keyword fallback for anything missing |
| 11 | Re-running would pay to tag the same posts again | No memory between runs | Cache tags per post + prompt version; only new posts go to the LLM |
| 12 | First live run: 10,005 posts fetched from 105 boards, but only 47 India fresher posts | Most of these companies hire mainly in the US (7,900 posts outside India); 1,268 India posts were senior; 790 India posts had titles like "Software Developer" that do not say the level | Titles that are clearly senior are dropped by rules; the 790 unclear ones now go to the LLM, which reads the description and keeps them only if 0–1 years / students / new grads are allowed |
| 13 | 112 of 217 company boards returned 404 | Many board names in the starting list were guesses, and some boards (Lever) are case-sensitive ("Sprinto", not "sprinto") | Removed the dead boards, added real ones found from live job links |
| 14 | "Operations Specialist, The Philippines (Remote)" was shown as an India job | Rule accepted any "Remote" post whose description mentioned India | Remote counts as India only when the location names no other place |
| 15 | Company names like "Rubrik Job Board", "HackerRank Careers", "Stable Money1" | Board names are not always the company name | `tidy_company()` strips these suffixes; unit-tested |
| 16 | Not enough fresher posts from documented APIs alone in November | Most internships open Jan–Mar; big MNC graduate programmes sit on Workday career sites | Turned on Workday (public career-site search, slow and limited) after weighing site terms; Workday lists "3 Locations", so the run opens those posts to read the real cities |
| 17 | Every LLM call failed: `create() got an unexpected keyword argument 'temperature'` | The current Anthropic SDK (2.9) no longer takes `temperature`; my unit test used a fake client, so it passed anyway | Removed the argument; added a test that checks every argument we send against the REAL SDK's signature |
| 18 | All 16 Workday career sites answered **429 Too Many Requests** on the first request from GitHub's servers | Workday blocks automated traffic from cloud servers | Respect it: no retries, no workarounds. The run logs "site refused automated requests" and moves on. More posts must come from company job-board APIs and AI screening |
| 19 | Claude API calls rejected: no credit on the account (free "evaluation" plan, $0 balance) | Assignment budget: I did not want to pay for a demo | Made the tagger provider-agnostic and moved to Gemini's free tier (no card). GitHub Models, the other free option, turned out to be retired since July 2026. Calls are paced to stay inside free-tier limits |
| 20 | Without an LLM, 42 of 54 live posts fell in "Other" | The keyword fallback only matched whole phrases ("software developer"), never "Software Development Engineer" | Gave each role a short keyword list for the fallback (the LLM still reads the descriptive hints); longer phrases win ties; whitespace normalised. "Other" dropped to 2 of 63; unit-tested on real titles |
| 21 | Daily run took 13 minutes even without an LLM | It opened ~800 descriptions that only an LLM can judge | Only open a description when it can be used (clear title, or an LLM is available) |
| 22 | The run's "save data" step failed: push rejected | I pushed a code fix while the run was going, so the run's copy was out of date | Before saving, the run pulls the latest code (rebase, its own data wins on conflict) and retries up to 3 times |
| 23 | 9 Workday posts stayed live after Workday was switched off | One or two Workday sites had answered in earlier runs; once the source was off, its boards were never checked, and "board not checked = probably down = keep" applied | A post from a board that is no longer in `config/companies.yaml` is closed at the next run; unit-tested |
| 24 | First run with the Gemini key: every call failed with 404 Not Found; 0 posts tagged, still 49 live | `gemini-2.5-flash-lite` is still served, but only to accounts that used 2.5 before; a new key cannot use it | Switched `llm.model` to `gemini-3.5-flash-lite` (Google's pick for new projects, free tier) in `config/settings.yaml`, no code change. The run did what S13 promises: 3 failed batches, then keyword fallback, and it still published |
| 25 | With working AI tags, only 86 live posts (target 200+) | The AI correctly turned down 691 of 777 unclear posts: most of these companies hire experienced people, and internships mostly open Jan–Mar. Most big Indian startups (PhonePe, Razorpay, Groww...) do not use the four public job-board APIs | Probed ~430 likely boards with the project's own filters; added the 15 that exist and have India posts the AI can judge (Swiggy, Sutherland, Endava, Sigmoid, HighRadius...). Did NOT relax "0–1 years": padding the count with jobs freshers cannot get would break the product's promise |
| 26 | Accuracy check: 2 of 50 sampled live posts are probably not fresher jobs ("mandatory experience", "lead cross-functional teams"), both from Bosch | Bosch titles say nothing about level, and the AI was a little generous when the description mixed "B.E." with experience wording | Noted in `eval/sample_50.csv`; role 94%, city 98%. Prompt v2 (`config/prompts/tagger_v2.md`): "mandatory/required experience" or leading a team means not entry-level, a degree alone is not enough, and field/on-site work is never Remote. Role hints now cover technical writing, post-sales engineers and AI research. New file name = new cache key, so every post is re-tagged once. Unit-tested. Result (run of 19 Nov): live 94 -> 93 (24 closed, 23 new). 20 of the 50 sampled v1 posts were dropped; at least 7 of them say "1–3 years", "1–2 years" or "1+ years" in the description, so v1 was letting experienced roles through. Technical Writer and Post-sales Engineer now get the right role. Still wrong: the Karya AI-evaluation intern stays "coding", and the field-marketing job is still "Remote" (the model ignored the rule). (These fixes came from the same 50 posts, so re-scoring that sample would flatter v2; a fresh sample is the fair test) |
